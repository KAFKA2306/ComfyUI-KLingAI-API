# ComfyUI Workflows Factory

## 超長期ミッション

世界中で公開・改良され続けるComfyUIのWorkflowを取り込み、創作に必要な生成技術を再利用できる共通基盤を育てる。独自のWorkflowを大量に作ること自体を目的にせず、実践者が生み出したWorkflow、Subgraph、Blueprint、モデルやCustom Nodeの組み合わせから学び、作品の完成と公開につなげる。

**達成するのは、次の8つの独立した制作ミッションすべてである。8つは同時並列に進める。** 並び順は優先順位でも開発順序でもない。ある領域の完成を、ほかの領域の開始条件にしない。

## 同時並列で達成する8つのミッション

| ミッション | 長期的に実現する成果 |
| --- | --- |
| **VRChatワールド** | 訪問でき、継続的に改善・公開できるワールドを制作する。小さなカフェから、落ち着く空間や体験型の世界まで扱う。 |
| **アバター・衣装** | VRChatなどで使えるキャラクター、衣装、テクスチャ、表情を制作し、対応アバターへの適合と実際の利用を確認する。 |
| **BOOTH商品** | 他者が入手・導入・利用できる3D素材、衣装、画像などを製品として仕上げ、説明・利用条件・配布物を整えて公開する。 |
| **YouTube・Shorts** | 解説、キャラクター映像、短編などを制作し、映像・音声・字幕・サムネイルまで含む動画を継続的に公開する。 |
| **Podcast・音声** | 説明、会話、物語、音楽以外の音響素材を含む音声コンテンツを制作し、聞ける完成形として配信する。 |
| **映画・アニメーション** | 物語、演出、動き、音声、編集を統合した映像作品を完成させ、鑑賞可能な形で公開する。 |
| **3Dモデル** | 画像や複数視点の入力から、編集・検証・再利用できる形状、テクスチャ、必要なリグを備えた3D資産を制作する。 |
| **ゲーム制作** | ルールと相互作用を持ち、実際に遊べるゲーム、ゲームワールド、キャラクター、背景、小物を制作・公開する。 |

各ミッションは固有の成果物、完成条件、進捗を持つ。共通のWorkflowや知見は相互に再利用するが、目標や完成判定をひとつにまとめない。

## 8つすべてを支える永続的な能力

1. **世界中の実践を継続的に取り込む。** 公式だけでなくコミュニティ、作者の配布、更新、改善事例を追い、見つかった候補を独自の人気評価や足切りで消さない。
2. **Workflowを中心に知識を蓄積する。** Workflowを制作・実行の主単位とし、SubgraphとBlueprintを再利用部品として関連付ける。作者、原典、ライセンス、版、依存関係、用途、確認状態を機械可読のメタデータで追跡する。
3. **再現と交換を可能にする。** 特定のモデル、GPU、作者、サービス、Custom Nodeの一時的な流行に依存しない。入力、設定、出力、版、実行環境、失敗を記録し、より良い公開実践へ置き換えられる構造を保つ。
4. **制作工程をつなぐ。** ComfyUIだけで完結することにこだわらず、Blender、Unity、VRChat、動画編集、音声編集、各公開先へ接続する。既存の制作リポジトリが持つ正本と完成判定を尊重する。
5. **生成と完成を混同しない。** 画像や素材が生成できても製品・作品の完成とはしない。各ミッションの実利用、品質、互換性、権利、公開結果で成果を確かめる。
6. **更新を継続し、採用を検証する。** 上流の変更を自動発見・記録する一方、未知のプログラムやモデルを無断で実行・導入しない。新旧の選択肢を出典と事実に基づいて利用できる状態に保つ。
7. **運用負荷を増やさない。** 重複台帳、形だけの文書、不要な階層を増やさず、長く維持できる小さな構造を選ぶ。Pythonの環境・依存関係の操作には必ず `uv` を使用する。
8. **日本語の設計知識を残す。** 人が読む文書は日本語を基本とし、確かな設計判断を残す。変わりやすい実装詳細やコマンドの正本はコード、設定、テストで管理する。

## 成功の定義

**8つのミッションがそれぞれ独立して制作・検証・公開まで進められ、その能力が時間とともに更新され続けること。** 一度のデモ、収集件数、スター数、生成成功だけでは達成としない。

このREADMEは長期間変わらない目的と原則だけを記す。日々の操作手順、利用中のモデル、実行環境、個別作品の状態、台帳はそれぞれのコード・設定・記録で管理する。
