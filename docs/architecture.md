# 構成と実装境界

## 現在の構成

公開元の設定 → 発見・収集 → 出典と版の保存 → 静的な形式確認 → 用途タグ付け → CSV・JSON・Markdownの一覧生成。

- `config/workflow_sources.json`：公開元と検索条件
- `src/gwp/discovery.py`：公開元の発見と更新記録
- `data/workflow_registry.json`：出典と版の収集台帳
- `scripts/build_catalog.py`：用途別索引の再生成
- `catalog/`：閲覧用と表計算用の生成結果
- `.github/workflows/workflow-discovery.yml`：定期的な収集

収集した候補をそのまま実行する機能ではない。

## 将来の制作工程

制作要求 → Workflow参照 → 依存関係とライセンス確認 → 環境準備 → ComfyUI実行 → 出力検証 → Blender・Unityなどへ受け渡し → 公開準備。

これは**一つの作品内の工程順**を表す。8つの制作領域を順番に進めるという意味ではなく、各分野は並列に運用する。

アプリケーションやエージェントの入力契約をComfyUIの内部ノードIDと分離する。実行アダプターが固定版Workflowに入力を割り当てる。モデル固有の変更が制作側の契約全体へ波及しないようにする。

## 境界と安全

- 公開元URL、ライセンス、コミット、ファイルハッシュ、ローカル変更履歴を保存する。
- 上流の更新検知と、制作環境への採用を区別する。
- 実行した場合はモデル版、設定、入力・出力ハッシュ、時間、VRAM、エラーを記録する。
- APIキー、モデル本体、生成メディア、個人情報、機密のローカルパスはGitへ入れない。
- 上流リポジトリ全体の複製を標準とせず、必要な公開資産の版を参照する。
